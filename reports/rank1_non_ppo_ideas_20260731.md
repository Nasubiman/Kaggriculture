# 1位公開データからの PPO 前改善案

調査日: 2026-07-31  
対象: 現在1位 Max Manushin（Leaderboard 1297.1）の直近公開10試合

## 結論

現在の1位は、単純な「牛16頭固定」ではない。序盤は作物と少数の羊で資金を作り、
9〜12日目に市場状態を見て、同じ28枠の牧草地を次のどちらかへ振り分けている。

- 牛多め: 牛22 + 羊6
- 羊多め: 牛12 + 羊16

直近10試合では、9日目終盤から10日目開始時点の市場価格だけを使う規則
`MILK >= WOOL なら羊多め、それ以外は牛多め` が10/10試合で実際のモードと一致した。
これは相手名や非公開情報を必要とせず、エージェントが直接観測できる。

10試合だけなので因果関係までは断定できないが、PPOより前に試すべき最も強い仮説である。

## 現在の main.py との差

| 項目 | 現在の main.py | 1位の公開10試合 |
|---|---:|---:|
| 家畜構成 | 牛16 + 羊4の固定 | 牛22+羊6 / 牛12+羊16を切替 |
| 最大家畜数 | 20 | 28前後 |
| 牛フェーズ開始 | 8日目 | 本格転換は10〜12日目 |
| 初期雇用 | 7人を目標 | おおむね3人 |
| 中盤雇用 | 11人を目標 | 11日目8人、12日目約11人 |
| 後半雇用 | 11人 | 18日目以降12人、最終盤は更新しない |
| 土地 | NEを1区画追加 | 同じく1区画追加 |
| 小麦 | 固定バッファ中心 | 売買を繰り返して在庫と現金を調整 |

配置については、現在の `main.py` も上位頻出の中心位置をかなり再現できている。
差の中心は配置そのものより、家畜数、牛羊比率、転換時期、雇用スケジュールにある。

## 観測された時系列

- 0〜1日目: メロン11〜12、羊2、雇用3人
- 2〜6日目: ニンジンを最大約11枚まで増やして初期資金を作る
- 7〜9日目: 小麦3枚、羊3〜4、雇用3〜4人
- 9日目終盤: MILK と WOOL の価格差で家畜モードを選べる状態になる
- 10日目: NE土地を購入し、牛を導入開始
- 11日目: 雇用8人、牛は平均約12頭まで急増
- 12日目: 雇用約11人、家畜合計はほぼ28頭に到達
- 13〜17日目: 雇用11人を維持
- 18〜26日目: 雇用12人を維持
- 27〜29日目: 契約切れを更新せず、11→10→0人へ減らす

1位は毎日同じ人数を雇うのではなく、必要作業量が増える転換日に合わせて労働力を買っている。
初期7人固定より、賃金を作物・土地・家畜購入へ回せる可能性が高い。

## PPOより前に行う学習・探索

### 1. 二値の家畜モード選択

10日目の観測から `cow-heavy` / `sheep-heavy` を選ぶ小さな分類問題として扱う。
最初は価格差の1ルールで十分で、その後リプレイを増やして次の特徴を加える。

- MILK, WOOLの価格と在庫、その差と比率
- 相手の牛・羊・作物数
- 解禁済みショップ
- 自分と相手の資金
- 座席、シード由来の市場推移

教師ラベルは、その試合で最終的に牛20頭以上なら牛多め、それ以外なら羊多めとする。
ロジスティック回帰や小さな決定木で十分であり、PPOは不要。

### 2. 段階的な雇用数

まずルールとして `3 → 4 → 8 → 11 → 12` の日別スケジュールを導入し、
ローカルArenaで各切替日をグリッド探索する。探索変数は5〜7個で済むため、
完全試合のブラックボックス最適化でも扱いやすい。

### 3. 28枠への拡張

現在の中心優先配置を残しつつ、NEを含む上半分に28牧草地を作る。
モードによって同じ枠へ牛と羊を割り当てれば、移動ロジックを大きく書き換えずに試せる。

### 4. 作物から家畜への転換日

現在の8日目固定と、1位に近い10日目転換を比較する。
評価は平均報酬だけでなく、両座席の勝率、下位10%のマージン、10日目現金、
12日目の家畜到達数を記録する。

### 5. 市場注文テンプレートの模倣

公開アクションには非常に大きな売買数量があるが、これは実行数量ではなく上限付き要求である。
1位は「全量売却」「残金で購入」を大きな数量で表現し、注文順で予算の優先順位を作っている。
特に小麦を同一日に売買するテンプレートが多く、固定在庫目標より市場価格と現金需要を
重視している可能性がある。実行数量をシミュレータ側で復元してから模倣対象にする必要がある。

## 推奨する実装順

1. 日10の価格差による牛羊モード切替
2. 家畜枠を28へ拡張
3. 雇用スケジュールを段階化
4. 転換日8〜10を探索
5. 小麦売買の実行数量を復元して市場ルールを改善
6. 上記ルールで十分な強さに達した後、残差だけを模倣学習/PPOで学ぶ

この順なら、ニューラル方策に全行動を学ばせず、公開データから明確に見える構造を
決定論的コードへ移せる。PPOは移動や日次運用全体ではなく、モード選択や市場判断で
手書き規則が取り切れない差分に限定できる。

## 注意点

- サンプルは直近10試合だけで、価格差ルールは過学習の可能性がある。
- 公開Game Historyは強い相手との試合に偏る。
- 市場価格は相手の行動と町の需要の両方を反映するため、単純な因果説明はまだできない。
- 変更は固定シード・両座席・複数相手でアブレーションし、一項目ずつ有効性を確認する。

再現用の集計は `scripts/analyze_rank1_adaptation.py`、
試合別の根拠表は `reports/rank1_current_adaptation.md` に出力する。
